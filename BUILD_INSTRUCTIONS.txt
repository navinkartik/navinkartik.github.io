1. OVERVIEW
================================================================================

This website uses Jekyll (GitHub Pages' built-in static site generator):

    YAML data files  --->  Jekyll (GitHub Pages)  --->  Generated HTML

You edit the YAML files (human-readable data), commit and push, and GitHub
Pages automatically generates the HTML. This means:

  - You only edit papers in ONE place (_data/papers.yml)
  - All three pages (index.html, published.html, unpublished.html) stay in sync
  - Coauthor URLs are consistent everywhere
  - You can still directly edit other parts of the HTML files (header, footer,
    teaching, contact info, etc.)


================================================================================
2. QUICK REFERENCE
================================================================================

After ANY change to _data/papers.yml or _data/coauthors.yml:

    git add -A
    git commit -m "Description of change"
    git push

GitHub Pages will automatically rebuild the site (usually within 1-2 minutes).

4. ADDING A NEW UNPUBLISHED PAPER
================================================================================

STEP 1: Check if coauthors exist in _data/coauthors.yml
-------------------------------------------------------
Open _data/coauthors.yml and check if all coauthors are listed. If someone is
missing, add them:

    Jane Smith: https://janesmith.com

Names must match EXACTLY when you use them in _data/papers.yml.


STEP 2: Add the paper to _data/papers.yml
-----------------------------------------
Open _data/papers.yml and add your new paper at the TOP of the file
(newest first):

    - title: "My New Paper Title"
      pdf: Papers/MyNewPaper.pdf
      coauthors: [Jane Smith, Alex Frankel]
      date: "January 2026"
      status: unpublished

Optional fields you can add:
    slides: Slides/MyNewPaper-slides.pdf
    links:
      - label: "Supplementary Appendix"
        url: Papers/MyNewPaper-appendix.pdf


STEP 3: Add the actual PDF file
-------------------------------
Copy your PDF to the Papers/ folder with the filename you specified.
If you have slides, copy them to the Slides/ folder.


STEP 4: Commit and push
-----------------------
    git add -A
    git commit -m "Add new paper: My New Paper Title"
    git push

GitHub Pages will rebuild the site automatically. Check your website in
1-2 minutes to verify the paper appears correctly.

5. ADDING A NEW PUBLISHED PAPER
================================================================================

Same as unpublished, but with additional required fields.

STEP 1: Check coauthors (same as above)

STEP 2: Add to _data/papers.yml
-------------------------------
Add at the TOP of the published section (after unpublished papers):

    - title: "My Published Paper"
      pdf: Papers/MyPublishedPaper.pdf
      coauthors: [Alex Frankel]
      journal: "American Economic Review"
      journal_url: https://www.aeaweb.org/articles?id=10.1257/aer.xxxxx
      pub_date: "March 2026"
      status: published

For forthcoming papers, use:
      pub_date: "forthcoming"

Optional fields:
      slides: Slides/MyPublishedPaper-slides.pdf
      links:
        - label: "VoxEU column"
          url: https://cepr.org/voxeu/columns/my-article
        - label: "Supplementary Appendix"
          url: Papers/MyPublishedPaper-appendix.pdf

STEPS 3-4: Same as unpublished

6. MOVING A PAPER FROM UNPUBLISHED TO PUBLISHED
================================================================================

When a paper gets accepted:

STEP 1: Find the paper in _data/papers.yml

STEP 2: Change status and add journal info
------------------------------------------
Before:
    - title: "My Paper"
      pdf: Papers/MyPaper.pdf
      coauthors: [Alex Frankel]
      date: "revised January 2026"
      status: unpublished

After:
    - title: "My Paper"
      pdf: Papers/MyPaper.pdf
      coauthors: [Alex Frankel]
      journal: "Econometrica"
      journal_url: https://doi.org/10.3982/ECTA12345
      pub_date: "forthcoming"
      status: published

STEP 3: Move the entry
----------------------
Cut the entire entry and paste it at the TOP of the published papers section
(after the last unpublished paper). The order in the file determines display.

STEP 4: Commit and push

8. REMOVING A PAPER
================================================================================

To remove a paper entirely:

1. Find the paper in _data/papers.yml
2. Delete the ENTIRE entry (from the "- title:" line to just before the next
   "- title:" line)
3. Optionally delete the PDF from Papers/ folder
4. Commit and push


================================================================================
9. HIDING A PAPER (DRAFT/PRIVATE)
================================================================================

To keep a paper in papers.yml without displaying it on the website, use any
status value other than "published" or "unpublished":

    - title: "My Draft Paper"
      pdf: Papers/Draft.pdf
      coauthors: [Someone]
      date: "January 2026"
      status: draft

The paper stays in the data file with all its metadata, but won't appear on
any page. When you're ready to make it public, just change the status:

    status: unpublished     (to show in unpublished section)
    status: published       (to show in published section)

You can use any status name you like:
    status: draft
    status: private
    status: hidden
    status: wip

This is useful for:
- Papers in progress that you want to track
- Papers you want to keep links to but not display yet
- Temporarily hiding a paper without deleting it

10. WORKING WITH COAUTHORS
================================================================================

ADDING A NEW COAUTHOR
---------------------
Edit _data/coauthors.yml and add a line:

    New Person Name: https://their-website.com

The name you use here must EXACTLY match what you put in _data/papers.yml.


UPDATING A COAUTHOR'S URL
-------------------------
If a coauthor changes their website:

1. Edit _data/coauthors.yml - find their name and change the URL
2. Commit and push

That's it! All papers with that coauthor will automatically use the new URL.


COAUTHOR NAME FORMATTING
------------------------
The name in coauthors.yml is exactly what appears on the website.

    Alex Frankel: https://...           # Displays as "Alex Frankel"
    Frances Xu Lee: https://...         # Displays as "Frances Xu Lee"

For names with special characters, use HTML entities:
    "S&eacute;bastien Turban": https://...    # Displays as "Sebastien Turban"


SOLO PAPERS (NO COAUTHORS)
--------------------------
For papers with no coauthors, use an empty list:

    coauthors: []

Or simply omit the coauthors field entirely.

11. PHD STUDENTS ON JOB MARKET
================================================================================

The PhD students section is directly in index.html (not in the data files).

ADDING/UPDATING STUDENTS
------------------------
Edit index.html and find this section:

    <h2>PhD Students on the job market</h2>
    <ul class="Papers">
    <li><a href="https://sites.google.com/view/tianhaoliuecon">Tianhao Liu</a>
    <li><a href="https://sites.google.com/view/yangfanzhou/">Yangfan Zhou</a>
    </ul>

To add a student:
    <li><a href="https://their-website.com">Student Name</a>

To remove a student:
    Delete their entire <li> line


REMOVING THE SECTION ENTIRELY
-----------------------------
When you have no students on the market, delete the entire section from
<h2>PhD Students... through </ul>

When you have students again, add it back.

13. PAPERS WITH SPECIAL FORMATTING
================================================================================

LONG COAUTHOR LISTS
-------------------
For papers with many coauthors, put them on a separate line:

    - title: "Paper with Many Authors"
      pdf: Papers/ManyAuthors.pdf
      coauthors: [Person One, Person Two, Person Three, Person Four]
      coauthors_on_next_line: true
      ...

This displays as:
    Paper Title
      with Person One, Person Two, Person Three, and Person Four


PAPER NOTES
-----------
For additional information below a paper (earlier versions, related notes):

    notes: "An earlier version was circulated under a different title"

For notes with links, use HTML:

    notes: |
      An earlier version: <a class="papertitle" href="Papers/OldVersion.pdf">Old Title</a>

The | character allows multi-line text.


NOTES INSIDE JOURNAL DIV (for published papers)
-----------------------------------------------
Some papers have notes that should appear inside the journal section:

    notes_inside_journal_div: true

NOTES IN DIV (instead of span)
------------------------------
    notes_in_div: true


EXTRA LINKS (beyond slides)
---------------------------
    links:
      - label: "VoxEU column"
        url: https://cepr.org/voxeu/columns/my-article
      - label: "Supplementary Appendix"
        url: Papers/MyPaper-appendix.pdf
      - label: "Replication code"
        url: https://github.com/...

14. COMPLETE FIELD REFERENCE
================================================================================

REQUIRED FOR ALL PAPERS:
------------------------
title           Paper title (in quotes if it contains colons)
status          "published" or "unpublished"

REQUIRED FOR UNPUBLISHED:
-------------------------
date            e.g., "January 2026" or "revised January 2026"

REQUIRED FOR PUBLISHED:
-----------------------
journal         Journal name
journal_url     URL to the journal article page
pub_date        e.g., "March 2026" or "forthcoming"

OPTIONAL FOR ALL:
-----------------
pdf                     Path to PDF file (e.g., Papers/MyPaper.pdf)
coauthors               List of coauthor names: [Name One, Name Two]
slides                  Path to slides PDF
links                   List of {label, url} pairs for extra links
notes                   Additional text/HTML below the paper
coauthors_on_next_line  true/false - put coauthors on separate line

OPTIONAL FOR PUBLISHED:
-----------------------
notes_inside_journal_div    true - puts notes inside the journal div
notes_in_div                true - wraps notes in <div> instead of <span>


================================================================================
15. YAML SYNTAX TIPS
================================================================================

QUOTES
------
Use quotes around titles containing colons:
    title: "Information Design: A Survey"

Use quotes around URLs with special characters:
    journal_url: "https://example.com?id=123&type=article"


LISTS
-----
Two formats work:

Inline (good for short lists):
    coauthors: [Alex Frankel, Wouter Dessein]

Multi-line (good for long lists or links):
    coauthors:
      - Alex Frankel
      - Wouter Dessein

    links:
      - label: "Appendix"
        url: Papers/appendix.pdf


MULTI-LINE TEXT
---------------
Use | for multi-line notes:

    notes: |
      First line of notes.
      Second line of notes.
      <a href="...">A link</a>


INDENTATION
-----------
YAML is indentation-sensitive. Use 2 spaces (not tabs) for each level:

    - title: "Paper"
      pdf: Papers/paper.pdf
      coauthors: [Name]
      links:
        - label: "Link"
          url: https://...

16. TROUBLESHOOTING
================================================================================

Site not updating after push
----------------------------
- Wait 1-2 minutes for GitHub Pages to rebuild
- Check the Actions tab on GitHub for build errors
- Verify you pushed to the correct branch

"Page build failure" email from GitHub
--------------------------------------
- Check YAML syntax (missing colons, bad indentation)
- Check Liquid syntax in HTML files (unclosed {% %} tags)
- View the Actions tab for detailed error messages

Coauthor link not appearing
---------------------------
- Check that the name in papers.yml EXACTLY matches coauthors.yml
- Names are case-sensitive
- Check for extra spaces

Paper not showing up
--------------------
- Check status is "published" or "unpublished" (spelled correctly)
- Check YAML syntax - a syntax error can cause papers to be skipped

PDF link broken
---------------
- Check the path in papers.yml matches the actual file location
- Paths are relative to the website root (e.g., Papers/file.pdf)
